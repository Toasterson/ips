# ADR-005: One Release Pipeline for All Tags, and pkg6depotd as an IPS/SMF Package

**Date:** 2026-09-23
**Status:** Proposed
**Issues:** [#41](https://code.aopc.cloud/OpenIndiana/ips/issues/41), [#25](https://code.aopc.cloud/OpenIndiana/ips/issues/25), [#8](https://code.aopc.cloud/OpenIndiana/ips/issues/8)

> Numbered 005 because ADR 004 is claimed by the parallel v1 atomic-import
> work. Renumber on merge if that changes.

## Context

The v1 decision (#24/#25) requires an OpenIndiana IPS package with SMF
integration that preserves operator configuration. Releases are cut as
`vX.Y.Z-alpha.N`, `-beta.N`, `-rc.N` and `vX.Y.Z`. CI runs on Solstice, which
ignores `needs:`, has no cross-job artifacts, clones with
`--depth=1 --no-tags`, expands `${{ env.* }}` to empty strings and caps each
job's wall clock at 6300 s by default.

The old `release.yml` built both platforms without tests, created releases as
published non-prereleases, and deleted and replaced assets of the same name on
re-runs.

## Decision

**Pipeline.** A single `release.yml` runs for every `v*` tag. Anything that is
not `vX.Y.Z` or `vX.Y.Z-(alpha|beta|rc).N` fails the first step. The two
platform jobs are identical in shape and independent of each other: verify
the tag, check the Cargo version, run the script self-tests, format check
(Linux), release build, nextest in the release profile, package, write
checksums and provenance, upload. Tests run in the release profile so the
illumos job compiles the workspace once, which keeps it within the job cap.

**Provenance.** Before building and again before uploading, the scripts
require the tag, `HEAD`, the runner's `GITHUB_SHA` and the tag as currently
published on origin to name the same commit. For an annotated tag, the
runner's `GITHUB_SHA` may instead be the tag object that peels to it. A moved or deleted tag fails.
An archive checkout without `.git` fails. Every crate version must equal the
tag. Each platform publishes `SHA256SUMS-<platform>` and
`provenance-<platform>.json`. The provenance records the tag object, commit,
tree, `Cargo.lock` hash, OS, toolchain and artifact hashes. It deliberately
leaves out host names and runner IDs, so clean re-runs produce identical
bytes. The repository is recorded as the canonical public URL. It is never
taken from the runner's git remote, which could embed credentials.

**Release state.** The release is created as a draft and flagged prerelease
for alpha, beta and rc. Assets are immutable: an existing asset is never
deleted or replaced. An identical re-upload is skipped. Different bytes, or
any addition to a non-draft release, fail the job. Tarballs are reproducible
so honest re-runs match. A pre-release is taken out of draft once every
platform's assets are present, by whichever job finishes last. A stable
release always stays a draft, and a maintainer publishes it.

**Package.** `pkg://openindiana.org/package/pkg6/depotd` delivers the following:

- `/usr/lib/pkg6depotd`, following the pkg5 `/usr/lib/pkg.depotd` convention.
- `pkg6repo`, `pkg6recv` and `pkgtree` in `/usr/bin`. Administration is local-only in v1.
- `pkg6depotd(8)`.
- `svc:/application/pkg/pkg6depotd`.
- The `pkg6srv` user and group with UID/GID 94, by analogy with `pkg5srv` (97). 94 is unassigned in oi-userland's registry.
- `/etc/pkg6depotd/pkg6depotd.kdl`: `root:pkg6srv`, mode `0640`, `preserve=renamenew`.
- No repository directory. `/var/pkg6depotd` is created by the operator:
  on uninstall, pkg(1) salvages unpackaged content of a removed directory
  into `/var/pkg/lost+found`, so delivering it would move the repository away.

Shared parent directories are implicit, as in oi-userland. This avoids
directory-attribute conflicts with OS packages.

`org.opensolaris.smf.fmri` is generated by `pkgdepend` from the SMF manifest,
not written in the template: a duplicate fails `pkglint.manifest006`. The
scratch publication repository is verified with `--disable dependency`. It
holds only this package, so dependency closure is checked by the live install
test instead.

IPS versions cannot carry SemVer pre-release tags. The channel therefore goes
in the branch:

| Tag channel | IPS branch |
|-------------|------------|
| alpha.N | `0.1.N` |
| beta.N | `0.2.N` |
| rc.N | `0.3.N` |
| stable | `1` |

This gives `1.0.0,5.11-0.1.1` < `…-0.3.2` < `1.0.0,5.11-1` < `1.0.1,5.11-0.1.1`.
The FMRI timestamp is the tagged commit's committer time.

**Service.** The service uses `startd/duration=child` and `--no-daemon`,
because `daemon::daemonize()` is a no-op. It runs as `pkg6srv` with the pkg5
depot privilege set: `basic,!file_link_any,!proc_info,!proc_session,net_privaddr`.
The illumos DTD has no `security_flags`, so the Solaris ASLR attribute is
omitted.

The default instance is delivered disabled. `pkg6depotd` no longer has
built-in defaults. It used to fall back to `0.0.0.0:8080` and `/tmp/pkg_repo`
when it could not load its config. Now a missing or invalid file, or anything
other than exactly one valid `bind` address, makes both `start` and
`config-test` fail. `config-test` does not open the repository. It prints
only the path, the bind address and the repository root, never the whole
configuration, which can hold credentials. The start
method also checks that the file is readable, so the failure is reported as an
SMF config error. `config/log_filter` sets `RUST_LOG`. The
package restarts the service when the binary or method changes, and disables
it before removal.

## Consequences

- Tagging requires a version-bump commit first. A tag on `0.5.3` code fails
  verification.
- Linux re-runs are clean. An illumos re-run fails closed once its `.p5p` is
  uploaded, because the archive embeds its publication time. A maintainer
  deletes the draft's assets for that platform, then re-runs. A re-run
  finishes a complete draft pre-release.
- The pkg6repo e2e tests run inside the workspace nextest gate. Each drives the
  `pkg6repo` binary Cargo built for the profile (`CARGO_BIN_EXE_pkg6repo`) in
  its own temporary directory. The fixtures are published through libips,
  because the old `pkg6dev` tool no longer exists.
- `release_check_test_inventory` runs in both CI and release. It enforces
  minimum counts for the required suites and allows exactly one unselected
  test: the opt-in OpenIndiana network test. `xtask` now fails when a command
  it spawns fails.
- The illumos job mutates its own VM's live image to test install, SMF,
  upgrade and uninstall. The test refuses to run without an explicit
  throwaway-VM flag.
- Before GA, UID/GID 94 must be registered in oi-userland
  `doc/reserved_uids_and_gids.md`. The `openindiana.org` publisher choice also
  needs maintainer confirmation.
